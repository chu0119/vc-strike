## 2. 入侵痕迹排查

### CVE-2026-59310（按可靠性排序）

```bash
# ① 全盘扫描目录外的 *-syslog.log（最可靠 —— 模板只会写在日志目录内）
find / -name '*-syslog.log' -not -path '/var/log/vmware/*' \
    -not -path '/storage/log/vmware/*' 2>/dev/null

# ② /etc/cron.d 异常条目（重点：带 -syslog.log 后缀）
ls -la /etc/cron.d/ && grep -rl 'syslog.log' /etc/cron.d/ 2>/dev/null

# ③ 遍历产生的畸形目录（rsyslog 会自动创建父目录）
ls -la / | grep -E '\.\.|%'
ls -la /var/log/vmware/ | grep -E '\.\.|%|rsyslog[^d]'

# ④ VAMI 静态目录被写入
ls -la /opt/vmware/share/htdocs/

# ⑤ 转发日志中的异常 APP-NAME/HOSTNAME（含 / 或 ..）
grep -nE '(\.\./|/)' /var/log/vmware/messages | head

# ⑥ statsreport webapp 异常文件
ls -la /usr/lib/vmware-perfcharts/tc-instance/webapps/statsreport/ \
    /usr/lib/vmware-perfcharts/webapps/statsreport/
```

**IOC（QUIRSO IR 案例留档）**：

- cron 名：`vmware-vpxd-stats-*`、`vmware-perf-collect-*`、`vmware-perf-sync-*`
- WebShell：statsreport 目录下 `vmware-perf-update.jsp` 类文件
- 辅助文件：statsreport 目录 `sso_domain.txt` 等非业务文件
- 本工具测试痕迹（自查授权测试是否清理干净）：
  `/etc/cron.d/cve59310*`、`/tmp/cve59310_*`、`/tmp/ws*-syslog.log`、
  `/opt/vmware/share/htdocs/r*.txt`

### CVE-2026-59309

- 网络侧：SASL SRP bind 报文中 A 字段以 RFC5054 素数 N（1024/2048 位）
  的前 32 字节开头（即 A=N 或 N 的整数倍）—— Mobeta 发布了对应 YARA。
- 目录侧：`cn=Users` 下异常账户（命名如 vcadmin / adminuser / pentest_*）、
  `cn=Administrators,cn=Builtin` 成员变更、vmdir 日志中的 SASL bind 异常。

## 3. 缓解（无法立即升级时）

1. **网络隔离（立即）**：514/1514 仅对受管 ESXi 与受信日志转发器开放；
   389/636/2020 限管理网。
2. **关闭 RFC5424 攻击面**：为 syslog 输入显式绑定 pmrfc3164：

   ```
   parser(name="p3164" type="pmrfc3164")
   input(type="imudp" port="514" ruleset="all" parser="p3164")
   ```

3. **omfile 路径净化**：`securepath="normal"` + `secpath-drop="replace"`
   （上游通告 GHSA-xmp9-244p-5ggv 指出 securepath 才是可靠路径边界）。
4. **阻断换行穿透**：`$EscapeControlCharactersOnReceive on`。
5. **收紧选择器**：`:app-name, startswith, "rsyslog"` 改精确匹配，
   hostname 规则按来源 IP/网段白名单。
6. **根因修复**：升级至修复版本（见上表）。

> ⚠️ 注意：当前挡住 `%hostname%` 向量的只是 RFC3164 解析器的默认行为这一
> "偶然防线"，并非可靠边界 —— 一旦为兼容性开启 `permit.slashesinhostname`
> 即失效。请以升级/securepath 为准。
