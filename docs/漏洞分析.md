# 漏洞分析：CVE-2026-59309 / CVE-2026-59310

> 本文是 VC-Strike 实现所依据的技术分析，供授权测试者与防御者参考。
> 上游材料：ChinaRan0 POC 仓库、QUIRSO IR 工件、Mobeta 技术分析、
> cyrus-sasl 2.1.26 `plugins/srp.c` 源码。

## 1. CVE-2026-59310 — syslog 路径穿越 → root RCE

### 1.1 成因（四个条件叠加）

1. **动态路径模板直接拼接不可信字段**（`/etc/rsyslog.conf`，VMware 出厂默认）：

   ```
   $template defaultLoc,      "/var/log/vmware/%app-name%/%app-name%-syslog.log"
   $template rsyslogadminLoc, "/var/log/vmware/%app-name%/%app-name%-syslog.log"
   $template esxLoc,          "/var/log/vmware/esx/%hostname%/%hostname%-syslog.log"
   ```

   `%app-name%` 同时用作目录名与文件名前缀，无路径净化。

2. **选择器过松**：`:app-name, startswith, "rsyslog"` 仅前缀匹配，
   `rsyslog/../../...` 即可命中规则进入动态模板。

3. **换行穿透**：`$EscapeControlCharactersOnReceive off` —— 报文 MSG 中的
   换行原样落盘，攻击者可控制写入文件的**行结构**（RCE 的关键）。

4. **解析器行为不一致（最易漏判的点）**：
   - RFC3164（pmrfc3164）：HOSTNAME/APP-NAME 用字符白名单，`/` 不放行
     → 在 `/` 处截断 → **无法遍历**；
   - RFC5424（pmrfc5424）：APP-NAME 是独立空格分隔字段，**不做字符校验**
     → `/` 与 `..` 原样保留 → **可以遍历**。
   - 服务端 `input(type="imudp" port="514")` 同时接受两种格式。

   旁证：纯 `..` 会被当作字面目录名（如 `rsyslog..`），说明 omfile 层
   不做 `..` 归一化 —— 决定成败的是解析器能否把 `/` 送进字段。

### 1.2 两条写入向量

| 向量 | 触发规则 | 载荷字段 | 回根方式 |
|---|---|---|---|
| `app`（默认） | `:app-name, startswith, "rsyslog"` | APP-NAME = `rsyslog/../../../../../<dest>` | 5 级 `..`（`/var/log/vmware/rsyslog/` 起算）|
| `host`（mobeta） | `$hostname != $$myhostname` | HOSTNAME = `../`×16 + `<dest>` | 16 级 `..`（`..` 在 `/` 处是 no-op，两次 `%hostname%` 展开收敛同一路径）|

写入文件名固定追加 `-syslog.log`；写入内容为
`"\n" + 可控内容 + "\n#"` —— 前导换行让可控行落到**第 0 列**，
尾部 `#` 注释掉模板自带尾部。

### 1.3 从写文件到 RCE

cron.d 接受文件名任意的配置文件（含 `-syslog.log` 后缀），要求行结构
`分 时 日 月 周 用户 命令`。首行（syslog 头部）触发 "bad minute" 被 crond
忽略，注入行被执行：

```
2026-01-05T12:00:00Z info rsyslog/../../../../../etc/cron.d/poc   ← bad minute，忽略
* * * * * root /bin/sh -c '{ id; } > /tmp/out.txt 2>&1'            ← root 执行
#
```

**回显通道（VC-Strike 扩展）**：把命令输出重定向到
`/opt/vmware/share/htdocs/`（VAMI lighttpd :5480 静态目录），再经
`https://<target>:5480/<file>` 读回 —— 无需目标能反向连通攻击机，
单边可达即构成完整 RCE→回显闭环。

**WebShell 落地**：syslog 先写 JSP 到 `/tmp`，cron 再 `cp` 成
`/usr/lib/vmware-perfcharts/tc-instance/webapps/statsreport/<name>.jsp`
（statsreport webapp），访问 `https://<target>/statsreport/<name>.jsp?c=id`。

### 1.4 修复与检测要点

- 修复版本把模板替换包裹 `secpath-replace`（如 `%hostname:::secpath-replace%`）。
- 检测：`grep -nE '%(app-name|hostname)%' /etc/rsyslog.conf`、全盘
  `find / -name '*-syslog.log'`（目录外命中即穿透过）、`/etc/cron.d/`
  带 syslog 后缀的条目、statsreport 目录异常 jsp。
- 详见 [检测与加固.md](检测与加固.md)。

## 2. CVE-2026-59309 — vmdird SRP 认证绕过

### 2.1 组件与攻击面

- 组件：`/opt/likewise/lib64/sasl2/libsrp.so.3.0.0`（Likewise 捆绑的
  Cyrus SASL SRP 机制插件），被 vmdird 用于 LDAP SASL bind。
- 端口：TCP 389（LDAP）/ 636（LDAPS）/ 2020（vmdird 内部端口）。
- 前置：无凭据，只需可达 + 一个**存在的身份串**（如
  `administrator@vsphere.local`）。

### 2.2 协议流程（对照 srp.c）

Cyrus SASL SRP 三次往返，均承载于 LDAP BindRequest 的 SASL credentials：

```
C1: { utf8(U) utf8(I) utf8(sid) os(cn) }
S1: { 0x00 mpi(N) mpi(g) os(s) mpi(B) utf8(L) }        ← N,g,s,B,服务端选项
C2: { mpi(A) os(M1) utf8(o) os(cIV) }                  ← A,客户端证据,选项,IV
S2: { os(M2) os(sIV) utf8(sid) uint(ttl) }             ← 服务器证据
```

缓冲区编码：`4B BE 总长 + 字段`；`%m`=2B 长度+MPI、`%o`=1B 长度+octets、
`%s`=2B 长度+UTF8、`%u`=4B BE。

### 2.3 漏洞本质：A ≡ 0 (mod N) 未校验

RFC 5054 §3.1 要求服务端拒绝 `A mod N == 0` 的公值。srp.c 的
`srp_server_mech_step2` 只有：

```c
/* Per [SRP]: reject A <= 0 */
if (BigIntCmpWord(&text->A, 0) <= 0) { ... }
```

发送 **A = N**（或 N 的任意正整数倍）后：

```
u = H(A || B)                     ← 公开
S = (v^u · A)^b mod N = 0         ← A ≡ 0 (mod N)，与口令验证元 v 无关
K = H(bytes(S)) = SHA1(b"")       ← BN_bn2bin(0) 输出空字节串
M1 = H( Ng ⊕ ⊕ || H(U) || s || A || B || K || H(I) || H(L) )
    Ng = H(bytes(N)) ⊕ H(bytes(g))；全部输入公开或自选 → 可伪造
```

服务端用相同公式自算 M1 与收到的比对 —— 一致即认证通过。
修复版新增 `BN_div` 检查并返回
`Illegal value for 'A' (A mod N == 0)`（VC-Strike 识别该报错并判定已修复）。

### 2.4 SASL 安全层（bind 之后的信道）

vmdird 通告 mandatory 层时，后续 LDAP PDU 走
`[4B BE 长度][AES-128-OFB 密文][HMAC-SHA1(20B)]` 帧：

- 密钥：AES 取 K 前 16 字节；HMAC 取完整 20 字节 K；
- IV：客户端加密用 **sIV**、解密用 **cIV**（服务端镜像相反）；
- HMAC 覆盖 `密文 + htonl(序号)`（replay 开启时），序号从 0 递增。

VC-Strike 内置纯 Python AES-128（FIPS-197 向量校验）实现该层，
从而绕过后可继续执行枚举/增删改查。

### 2.5 影响

以任意存在身份获得 SSO 目录完整读写：
枚举用户/组、创建管理员账户并加入 `cn=Administrators,cn=Builtin`、
重置任意账户 `userPassword`（含 administrator）→ 直接登录
`https://<vcenter>/ui` 获得虚拟化管理面控制权。

### 2.6 检测要点

- 网络侧：SASL SRP bind 中 A 字段以 RFC5054 素数 N（1024/2048 位）
  前 32 字节开头（即 A=N/k·N）的报文 —— Mobeta 提供 YARA 特征。
- 主机侧：cn=Users 异常账户、Administrators 成员变更审计。

## 3. 组合与后渗透

```
59310 RCE ──→ lwregshell 提取 dcAccountDN/dcAccountPassword（机器账户）
              ├→ 机器账户直连 LDAPS（合法 bind，同样全权）
              └→ 横向 ESXi 管理面凭据复用
59309 建管 ──→ /ui 登录 ──→ 与 statsreport WebShell 组合
```

IR 案例（QUIRSO）中 actor 的完整路径为 59310 → 凭据提取 → SSO 隐藏
管理员 → ESXi 勒索。VC-Strike 只实现到凭据/权限证明，
不移植破坏与隐蔽持久化部分（安全边界）。
